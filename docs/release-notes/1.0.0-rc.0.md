# Easy CMS 1.0.0-rc.0

The first release candidate of **Easy CMS 1.0**, the first version meant for production use.
Please try it and [report anything that breaks](https://github.com/maritonx/easy-cms/issues/new).
1.0.0 is planned for 2026-12-15.

## Try it

The release candidate is on the `rc` tag; `latest` stays on 0.68 until 1.0.0.

```bash
# A new project (pnpm, Yarn 4 and Bun: `pnpm create easy-cms@rc`…;
# Yarn 1: `npx create-easy-cms@rc --pm yarn`)
npm create easy-cms@rc

# An existing one: every package together
npm install @easy-cms/core@rc @easy-cms/db-sqlite@rc easy-cms@rc  # and your adapter, plugins…
npx easy-cms migrate
```

Upgrading from 0.x? Back up first and follow
[From 0.x to 1.0](https://easy-cms-website.vercel.app/docs/upgrading#to-1-0): what changed, a
checklist of the changes that don't stop your app, and the steps.

## What 1.0 promises

From 1.0, breaking changes come only in a major release, with an upgrade guide; minor releases
add features and patch releases fix bugs. The promise covers the config, the Local API, REST
routes and error codes, the CLI, adapters, and your data: upgrades migrate it forward, and CI
upgrades databases made by releases back to 0.10 on every commit. Renamed APIs keep working until
the next major, with a warning. Details: [Versions and
deprecations](https://easy-cms-website.vercel.app/docs/versioning).

Not covered yet: `@easy-cms/plugin-ecommerce`, `@easy-cms/plugin-graphql` and
`@easy-cms/plugin-mcp` are [experimental](https://easy-cms-website.vercel.app/docs/versioning#experimental).
They are tested with real services and clients (Stripe, urql with codegen, Claude), but may
still change in a minor release until they are declared stable.

## Since 0.48

- **API settled (0.60):** consistent names across config, Local API, REST and plugins;
  `apiVersion` for plugins; deprecation warnings for old names.
- **Security (0.62–0.66):** a self-review against OWASP ASVS level 1. Common passwords refused,
  `__Host-` cookies and HSTS, 404 for documents you can't read, encrypted backups, GraphQL
  introspection off in production, SMTP over TLS, tenant-aware audit log.
- **Plugins ready for production (0.67–0.68):** a fixed Stripe API version, GraphQL with
  `graphql` 16 and 17 as a peer, MCP tested through the SDK client and with Claude, React and Vue
  shop hooks tested.
- **Fixes found on the way:** `<easy-form>` kept in production bundles; `useAddresses()` without
  unhandled rejections; payment methods in the page's language; direct uploads of large files.

The full list is in each package's CHANGELOG.

## Help test

- Follow [Getting started](https://easy-cms-website.vercel.app/docs/getting-started) on a fresh
  project with Next.js, Nuxt or the standalone server, and tell us where it doesn't match.
- Upgrade a real 0.x project with the guide above.
- Security issues: please report them privately, as in
  [SECURITY.md](https://github.com/maritonx/easy-cms/blob/main/SECURITY.md).
