# ADR-0068: กฎการเข้าสู่ระบบในหน้า admin

- **สถานะ:** Accepted
- **วันที่:** 2026-11-13
- **เกี่ยวข้อง:** [ADR-0066](0066-admin-overrides-code-defaults.md), [#409](https://github.com/maritonx/easy-cms/issues/409)

## บริบท

- 1.43 ย้ายผู้ให้บริการเข้าสู่ระบบไปตั้งในหน้า admin ได้ (ADR-0066) แต่กฎว่าใครเข้าได้ยังอยู่ในโค้ดเท่านั้น:
  `auth.password` (ใครใช้รหัสผ่านได้) และ `auth.providerSignUp` (ใครสมัครเองได้)
- เป็นเรื่องความปลอดภัยโดยตรง ตั้งผิดแล้วองค์กรล็อกตัวเองออก หรือเปิดให้คนนอกสมัครเข้ามา (grilling 2026-11-13)

## การตัดสินใจ

- **ขอบเขต:** `auth.password` และ `auth.providerSignUp` ส่วนการสมัครของ site members (`auth.members`) แยกเป็นเรื่องอื่น
- **ที่อยู่:** แผง "ใครเข้าสู่ระบบได้" ใน Settings → Single sign-on ซึ่งแสดงกฎนี้อยู่แล้ว (ไม่ใช่ Integrations → Sign-in
  ที่เป็นหน้าการเชื่อมต่อ)
- **ลำดับค่าและการล็อกตาม ADR-0066:** ค่าที่ admin ตั้ง → ค่าในโค้ด, บันทึกค่าเท่ากับในโค้ด = ไม่เก็บ,
  ปุ่ม "ใช้ค่าจากโค้ด", `auth.locked` ตัวเดิมล็อกด้วย, เฉพาะ admin ของทั้งเว็บ, ลง audit log (`sign-in.rules`),
  แต่ละเซิร์ฟเวอร์อ่านใหม่ทุก 30 วินาที
- **นโยบายรหัสผ่านมีผลทันทีที่บันทึก:** session ที่เข้าด้วยรหัสผ่านของบัญชีที่ใช้ไม่ได้แล้วถูกตัด
  (session ที่เข้าด้วยผู้ให้บริการไม่ถูกตัด) ก่อนบันทึกหน้า admin บอกผลกระทบ (`?dryRun=1`): กี่บัญชีเสียรหัสผ่าน กี่ session ถูกตัด
- **ตัวกันล็อกตัวเอง:** ไม่ยอมบันทึกถ้าหลังเปลี่ยนไม่มี admin คนไหน **หรือคนที่กดบันทึกเอง** เข้าสู่ระบบได้
- **บัญชี break-glass จากหน้า admin:** เลือกจากผู้ใช้จริงที่ active และมีรหัสผ่าน ต้องมี admin อย่างน้อย 1 คน
  เก็บเป็น user id (อีเมลเปลี่ยนได้) และไม่ยอมลบ ปิด ลด role หรือเอารหัสผ่านออกจาก admin คนสุดท้ายในรายชื่อที่ใช้รหัสผ่านได้
- **การสมัครเอง:** ใช้กับผู้ให้บริการทุกตัว ห้าม role `admin` และ role ที่ Create/Update/Delete บน Users ได้ (RBAC)
  ห้ามโดเมนอีเมลสาธารณะ (รายชื่อราว 20 เจ้าใหญ่ใน core ไม่ใช้แพ็กเกจภายนอก) ถ้าไม่มีผู้ให้บริการเปิดอยู่ กฎไม่มีผล
  แต่ยังปิดผู้ให้บริการได้
- **ค่าเดียวกันใน config:** เตือนใน log ตอนเริ่มและในหน้า Single sign-on ยังไม่ error เพราะ 1.x สัญญาว่าไม่ breaking
  เปลี่ยนเป็น error ใน 2.0
- **ไม่ส่งอีเมล**ถึงคนที่ได้รับผลกระทบ หน้า login คำเชิญ และ "ลืมรหัสผ่าน" ปรับตามนโยบายอยู่แล้ว
- **`easy-cms reset-sign-in`** ล้างทั้งผู้ให้บริการและกฎ กลับไปใช้ค่าในโค้ดทั้งหมด

## ผลที่ตามมา

- `cms.auth.sso.passwordAllowed()` กลายเป็น async เพราะนโยบายอยู่ในฐานข้อมูล
- ค่าที่บันทึกไว้ว่านโยบายไหนใช้ล่าสุด (`easy-cms:password-policy`) อัปเดตทั้งตอนเริ่มและตอน admin บันทึก
  การอัปเกรดจึงไม่ถูกนับเป็นการเปลี่ยน
- 2.0: กฎที่หน้า admin ห้ามจะเป็น error ใน config ด้วย
