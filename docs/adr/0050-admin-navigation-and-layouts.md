# ADR-0050: เมนูเป็นกลุ่ม, command palette และ layout ของหน้าแก้ไข

- **สถานะ:** Accepted
- **วันที่:** 2026-10-09

## บริบท

plugin เพิ่มขึ้นเรื่อยๆ (ร้านค้า ฟอร์ม multi-tenant SEO) เมนูซ้ายจึงยาวและแบน มีแค่ "เนื้อหา" "หัวข้อที่ตั้งเอง" และ "ตั้งค่า" ที่มีมากกว่า 10 รายการ
หน้าของ plugin กับ global จัดกลุ่มไม่ได้ หน้าแก้ไขเรียง field ยาวลงมาแถวเดียว ไม่มีแท็บ ส่วนที่พับได้ แถว หรือ field ที่แสดงตามเงื่อนไข
ไม่มีการค้นหาข้าม collection และบันทึกไม่ผ่านแล้วผู้ใช้ต้องหาเองว่าผิดตรงไหน

## การตัดสินใจ

- **เมนู:** กลุ่มที่พับได้ลึก 2 ชั้น ประกาศใน `admin.nav` (`{ id, label, icon, order, children }`) แล้ว collection, global และหน้าอ้างถึงด้วย
  `admin.group: 'shop.catalog'` server สร้างผังเมนูต่อผู้ใช้ (`AdminSchema.nav`) จากสิทธิ์ของแต่ละคน กลุ่มที่ว่างไม่แสดง
  - กลุ่มในตัว: `content` (0), คลังสื่อเป็นรายการเดี่ยว (10), `settings` (1000) ที่มี `site`, `people`, `system` ประกาศ id เดียวกันเพื่อแก้ชื่อ ไอคอน ลำดับ
    (ประกาศก่อนชนะ config ของเว็บมาก่อน plugin)
  - ของเดิมยังใช้ได้: `group: 'settings'` ไปที่ ตั้งค่า › เว็บไซต์, label สร้างกลุ่มให้, `admin.menu` เรียงภายในกลุ่ม, `AdminPage.group` รับ id ด้วย
  - badge: `admin.badge { where, tone, label }` นับตามสิทธิ์ของผู้ใช้ผ่าน `GET <api>/admin/counts` (แทนการยิง request ต่อ collection) และ `admin.count: false`
  - สิ่งที่แต่ละคนปรับ (พับ ปักหมุด หุบเหลือไอคอน) เก็บใน localStorage ไม่ต้องเปลี่ยนฐานข้อมูล
- **Command palette (⌘K):** ไปที่ สร้าง ค้นหาเอกสาร (`GET <api>/admin/search?q=` ค้นชื่อเรื่องและ id ทุก collection ที่อ่านได้) เปิดล่าสุด และคำสั่ง
  (`admin.commands`) พร้อมคีย์ลัด `⌘S`, `⌘⇧P`, `[`, `/`, `g d`, `?`
- **Layout ของหน้าแก้ไข เป็น `admin.layout` ที่อ้างชื่อ field ไม่ใช่ชนิด field ใหม่:** ตอนคุยกันตกลงจะเพิ่มชนิด field `tabs`/`collapsible`/`row` แบบ Payload
  แต่ field ที่ไม่มีชื่อต้องแก้ทุกจุดที่วนอ่าน field ใน core, plugin และการ infer type ทั้งหมด การแยก layout ไว้ใน `admin` ได้ความสามารถเท่ากัน
  (แท็บ ส่วนที่พับได้ แถว `admin.width`) โดยข้อมูลและ type ไม่เปลี่ยน และ plugin เพิ่มแท็บได้ง่าย (SEO เพิ่มแท็บของตัวเอง) ใช้กับ field ชั้นบนสุดก่อน
- **`admin.condition` แบบประกาศ:** `{ field, equals | notEquals | in | exists }` กับ `and`/`or`/`not` ไฟล์เดียวที่ไม่พึ่ง Node (`@easy-cms/core/conditions`)
  ใช้ทั้งใน admin (ซ่อน field) และ server (ไม่บังคับกรอก field ที่ถูกซ่อน รวมถึงข้างใน group/array ที่ถูกซ่อน)
- **การบันทึก:** กล่องสรุปข้อผิดพลาดที่รับโฟกัส เปิดแท็บและส่วนของช่องแรก แท็บแสดงจำนวนช่องที่ผิด ร่างที่ยังไม่บันทึกเก็บในเครื่องและถามว่าจะกู้คืนไหม
- **อื่นๆ:** `admin.description`, `admin.empty`, แผงในแถบข้าง `position: 'top'`, หน้ารายการจำคำค้น ตัวกรอง และ scroll เมื่อกดกลับ,
  ลิงก์ข้ามไปเนื้อหา และโฟกัสย้ายไปที่หัวข้อเมื่อเปลี่ยนหน้า
- **plugin:** ร้านค้าใช้กลุ่ม `shop` (แคตตาล็อก การขาย ลูกค้า) แท็บสินค้า badge คำสั่งซื้อรอจัดส่ง และคำสั่งใน ⌘K ฟอร์มใช้กลุ่ม `forms`
  multi-tenant อยู่ที่ ตั้งค่า › ผู้ใช้และสิทธิ์ และ SEO ย้ายไปแท็บของตัวเอง (`tab: false` เพื่อคงแบบเดิม)

## ผลที่ตามมา

- config เดิมทำงานต่อได้ ไม่ต้องสร้าง migration เพราะไม่เปลี่ยนฐานข้อมูล ส่วนที่หน้าตาเปลี่ยนคือ SEO ที่ย้ายไปแท็บ
- `AdminCollection.group`/`section` และ `AdminPageRef.group` ใน admin schema ถูกแทนด้วย `AdminSchema.nav`
- ยังไม่ทำ: layout ข้างใน group/array/blocks, saved views, ตัวกรองหลายเงื่อนไข, export CSV ทุก collection, dashboard ที่จัดเองได้,
  ค่าของผู้ใช้เก็บที่ server, โหมด compact, เลิกทำการลบ และแก้เมนูจากหน้า admin
