# ADR-0012: Version history และการแยกฉบับร่างออกจากเวอร์ชันที่เผยแพร่

- **สถานะ:** Accepted
- **วันที่:** 2026-09-27

## บริบท

ใน v0.1–0.2 เอกสารมีสำเนาเดียว การบันทึกเอกสารที่เผยแพร่แล้วเป็นฉบับร่างจึงยกเลิกการเผยแพร่ไปด้วย ([ADR-0008](0008-media-drafts-hooks.md)) ทำให้แก้ไขเนื้อหาที่ออนไลน์อยู่อย่างปลอดภัยไม่ได้ และไม่มีประวัติให้ย้อนกลับ ทั้งสองเรื่องเป็นพื้นฐานของ live preview ในอนาคตด้วย

## การตัดสินใจ

- **Opt-in ด้วย `versions: true | { max }`** ต่อ collection/global ค่า `max` เริ่มต้น 50 เวอร์ชันต่อเอกสาร collection ที่ไม่เปิดทำงานเหมือนเดิมทุกอย่าง
- **ตารางเดียว (`ecms_document_versions`)** เป็น internal collection (`parent`, `doc`, `status`, `latest`, `author`, `snapshot` แบบ JSON) ใช้กลไก schema/migration เดิมทั้งหมด และเพิ่มเข้า schema เฉพาะเมื่อมีการเปิด versions โปรเจกต์ที่ไม่ใช้จึงไม่ต้องสร้าง migration ใหม่ snapshot เก็บเอกสารทั้งก้อน (ไม่ใช่ diff) และไม่เก็บ field ที่ `hidden`
- **`latest`** ระบุสถานะปัจจุบันที่แก้ไขได้ของเอกสาร ถ้าเอกสารหลักเป็น `published` แต่ `latest` เป็น `draft` แปลว่ามีฉบับร่างรอเผยแพร่ การอ่านแบบ `draft: true` (รวมถึงการ populate) จะแทนด้วยฉบับร่างนั้น การอ่านปกติได้เอกสารหลักที่เผยแพร่อยู่
- **แยกฉบับร่าง** (เมื่อมีทั้ง `drafts` และ `versions`): `update` ที่ได้ `status: 'draft'` กับเอกสารที่เผยแพร่อยู่จะบันทึกเป็นเวอร์ชันอย่างเดียว ไม่แตะแถวหลัก การแก้ไขบางส่วนจะ merge กับฉบับร่างที่รออยู่ hooks และ validation ทำงานเหมือนการบันทึกปกติ การเผยแพร่เขียนแถวหลักแล้วบันทึกเวอร์ชัน `published` เป็น latest
- **คำสั่งใหม่:** `unpublish` (เดิมคือ update เป็น draft ซึ่งตอนนี้กลายเป็น "บันทึกฉบับร่าง"), `discardDraft` (บันทึกเอกสารหลักเป็นเวอร์ชันล่าสุดอีกครั้ง ฉบับร่างที่ทิ้งยังอยู่ในประวัติ), `findVersions`/`findVersion`/`restoreVersion` และชุดเดียวกันของ globals การกู้คืนเป็นการ `update` ตามปกติ (มีสิทธิ์, hooks, validation) และถ้ามีฉบับร่างจะกู้คืนเป็นฉบับร่าง
- **สิทธิ์:** อ่านเวอร์ชันได้เฉพาะผู้ที่มีสิทธิ์ `update` เอกสารนั้น เพราะเวอร์ชันมีเนื้อหาที่ยังไม่เผยแพร่
- **REST:** `/:collection/:id/versions[/:v[/restore]]`, `/unpublish`, `/discard-draft` และชุดเดียวกันใต้ `/globals/:slug/`
- **Admin:** แผง History (ดูเวอร์ชันแบบอ่านอย่างเดียวแล้วกู้คืน) badge "Unpublished changes" และปุ่ม Publish changes / Save draft / Discard changes / Unpublish ส่วนหน้า list ดึง id ที่เผยแพร่อยู่เพิ่มอีกหนึ่ง request เพื่อแสดงสถานะที่ถูกต้อง

## ผลที่ตามมา

- ✅ แก้เนื้อหาที่ออนไลน์อยู่ได้อย่างปลอดภัย และย้อนกลับได้
- ✅ ไม่กระทบโปรเจกต์ที่ไม่เปิด versions (ไม่มี migration และพฤติกรรมไม่เปลี่ยน)
- ❌ `where` และการเรียงลำดับใช้ข้อมูลที่เผยแพร่อยู่ ไม่ใช้ข้อมูลของฉบับร่างที่รออยู่
- ❌ การบันทึกเวอร์ชันไม่ได้อยู่ใน transaction เดียวกับการเขียนเอกสาร ถ้าล้มกลางทางอาจได้เอกสารที่ไม่มีเวอร์ชันล่าสุด (ข้อมูลหลักยังถูกต้อง)
- ❌ snapshot เป็นเอกสารทั้งก้อน ใช้พื้นที่มากกว่าการเก็บ diff (จำกัดด้วย `max`)
