# ADR-0041: โฟลเดอร์ในคลังสื่อ

- **สถานะ:** Accepted
- **วันที่:** 2026-10-07

## บริบท

- คลังสื่อเป็นรายการเดียวยาวๆ เมื่อไฟล์มากขึ้นทีมหาไฟล์ยาก และอยากแยกตามงานหรือแผนก
- องค์กรอยากให้แต่ละทีมเห็นและแก้เฉพาะไฟล์ของตัวเอง เช่น ทีมการตลาดกับ HR แต่บทบาท (`auth.rbac`) กำหนดสิทธิ์ได้แค่ทั้ง collection `media`
- ไฟล์ทุกไฟล์เป็นสาธารณะ เสิร์ฟจาก `/media/file/<key>` หรือ CDN ของ storage โดยไม่ตรวจสิทธิ์

## การตัดสินใจ

- **เปิดเองด้วย `upload.folders: true`** เพิ่ม collection `media-folders` (`name`, `parent`, `permissions`) และ field `folder` ของ `media` เฉพาะเมื่อเปิด โปรเจกต์เดิมจึงไม่มีตารางใหม่โผล่มาเอง starter template เปิดไว้
- **โฟลเดอร์ซ้อนได้ ไฟล์อยู่ได้โฟลเดอร์เดียว** ทำให้ตัดสินสิทธิ์ได้ชัด (ถ้าไฟล์อยู่ได้หลายหมวด สิทธิ์จะขัดกัน) แท็กเพิ่มเป็น field เองได้ ชื่อไม่ซ้ำในโฟลเดอร์เดียวกัน (ไม่สนตัวพิมพ์) และย้ายโฟลเดอร์เข้าไปในตัวเองไม่ได้ ตรวจใน Local API ก่อนเขียน
- **โฟลเดอร์เป็นแค่ข้อมูล** ไม่เปลี่ยน key ของไฟล์ใน storage ย้ายได้ทันทีและ URL ไม่เสีย เหมือน Payload, Strapi และ WordPress
- **ลบโฟลเดอร์ย้ายของข้างในขึ้นไปที่แม่** ไม่ลบไฟล์ เพราะไฟล์อาจยังถูกใช้ในเนื้อหา
- **สิทธิ์ตั้งที่โฟลเดอร์ สืบทอดลงไป:** `permissions` เป็น `null` (ตามแม่) หรือระดับของแต่ละบทบาท `view` / `edit` / `manage` บทบาทที่ไม่อยู่ในรายการไม่เห็นโฟลเดอร์ ชั้นนอกสุดเปิดให้ทุกบทบาท ระดับที่ใช้ต่อ operation: อ่านต้อง `view` แก้หรือลบไฟล์และใส่ไฟล์เข้าโฟลเดอร์ต้อง `edit` สร้าง แก้ ย้าย หรือลบโฟลเดอร์ต้อง `manage`
- **AND กับสิทธิ์ของบทบาท:** `checkGrant` เพิ่มเงื่อนไขโฟลเดอร์ (`folder in […]` หรือไม่มีโฟลเดอร์) ต่อจากสิทธิ์ของบทบาท ใช้หลัก "code access AND role grants" เดิม โฟลเดอร์จึงทำได้แค่จำกัดให้แคบลง `media-folders` ไม่มีแถวใน Settings → Roles และ API key แต่ใช้สิทธิ์ `media` (เฉพาะเอกสารของตัวเอง = โฟลเดอร์ที่ตัวเองสร้าง)
- **มีผลเฉพาะผู้ใช้ที่ login** ไม่ใช่ admin และไม่ใช่ API key ผู้ที่ไม่ได้ login ยังอ่านข้อมูลไฟล์ทุกไฟล์ได้เหมือนเดิม เอกสารเขียนชัดว่าเป็นการแบ่งงานของทีม ไม่ใช่การซ่อนไฟล์ ไฟล์ส่วนตัวจริงเป็นงานของ 0.39 (`privateStorage`, route ที่ตรวจสิทธิ์, `signedMediaURL`) ซึ่งตั้งที่โฟลเดอร์เหมือนกัน รายชื่อโฟลเดอร์อ่านได้เฉพาะผู้ที่ login เพราะชื่ออาจบอกข้อมูลภายใน
- **คำนวณในหน่วยความจำ:** โหลดโฟลเดอร์ทั้งหมด (id, parent, permissions) ครั้งเดียวต่อ 10 วินาที และล้างเมื่อเขียนโฟลเดอร์ใน process เดียวกัน (หลาย server อาจเห็นสิทธิ์เก่าได้ไม่เกิน 10 วินาที แนวเดียวกับ Roles) โฟลเดอร์มีจำนวนน้อยเมื่อเทียบกับไฟล์ จึงไม่ต้องใช้ recursive query ที่ต่างกันในแต่ละฐานข้อมูล
- **ตั้งสิทธิ์ได้เฉพาะ admin:** field `permissions` อ่านและแก้ได้เฉพาะ admin ที่ login (ไม่ใช่ API key) role ที่ไม่มีอยู่จริงหรือระดับที่ไม่รู้จักถูกปฏิเสธ การเปลี่ยนบันทึกใน audit log เป็น `folder.permissions` แยกจาก `update`
- **admin:** หน้า Media มีต้นไม้โฟลเดอร์ (ซ่อนบนจอเล็ก) breadcrumb การ์ดโฟลเดอร์ย่อย ลากไฟล์ไปวาง "ย้ายไป…" อัปโหลดลงโฟลเดอร์ที่เปิด และค้นในโฟลเดอร์กับโฟลเดอร์ย่อย ตัวเลือกไฟล์เรียกดูโฟลเดอร์และจำโฟลเดอร์ล่าสุดในเครื่อง โฟลเดอร์ส่ง `level` ของผู้อ่านมาด้วย (afterRead) เพื่อให้ admin แสดงเฉพาะปุ่มที่ใช้ได้ ช่อง upload ที่ชี้ไปไฟล์ที่มองไม่เห็นแสดง "ไฟล์ที่ไม่มีสิทธิ์ดู" และค่าไม่หายตอนบันทึก (admin โหลดเอกสารแบบ `depth=0`)

## ผลที่ตามมา

- ✅ จัดคลังสื่อเป็นโฟลเดอร์ และแบ่งงานของแต่ละทีมได้โดยไม่ต้องเขียนโค้ด
- ✅ ไม่กระทบโปรเจกต์ที่ไม่เปิด และ URL ของไฟล์ไม่เปลี่ยน
- ⚠️ ไฟล์ยังเป็นสาธารณะจนถึง 0.39 คนที่มีลิงก์ยังเปิดได้
- ❌ ยังให้ช่อง upload ในโค้ดระบุโฟลเดอร์ไม่ได้ (ใช้โฟลเดอร์ล่าสุดแทน) และ API key ยังจำกัดตามโฟลเดอร์ไม่ได้
