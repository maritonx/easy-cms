# ADR-0035: Backups จากหน้า admin

- **สถานะ:** Accepted
- **วันที่:** 2026-10-04

## บริบท

- Easy CMS ไม่ได้ backup ให้ เอกสารบอกให้ผู้ใช้ทำเอง (`easy-cms backup` ได้เฉพาะ SQLite, Postgres ใช้ `pg_dump`) คนส่วนใหญ่จึงไม่มี backup
- `pg_dump` เป็นโปรแกรมภายนอกที่เรียกจาก Node ไม่ได้เสมอไป (ไม่มีบน serverless หรือ container ส่วนใหญ่)

## การตัดสินใจ

- **ไฟล์ SQLite บีบอัดไฟล์เดียวสำหรับทุกฐานข้อมูล** (`<site>-YYYY-MM-DD-HHmm.db.gz`, `writeBackupFile`)
  - SQLite ใช้ `VACUUM INTO` (`Database.backup`)
  - Postgres คัดลอกด้วย `copyDatabase` ลงไฟล์ SQLite ชั่วคราว แล้ว `VACUUM INTO` อีกครั้งให้ได้ไฟล์เดียวที่สมบูรณ์ เพราะ libSQL เก็บการเขียนล่าสุดไว้ในไฟล์ WAL (พบตอนทดสอบ: ไฟล์หลักว่าง)
  - ใช้ `tablePrefix` เดียวกับต้นทาง (`Database.tablePrefix` ใหม่) เพราะ schema hash และชื่อตารางขึ้นกับ prefix
  - core ไม่มี driver ของ SQLite จึงให้ config ส่ง adapter มาเอง (`backups.sqlite`) แทนการ import แบบ dynamic ที่ bundler ของ Next.js/Nuxt ตามไม่เจอ
- **config ในโค้ด แก้ในหน้า admin ไม่ได้:** `backups: { every?: 'day' | 'week', at = '03:00', keep = 7, dir = 'backups', storage?, sqlite? }` ไม่ตั้ง `every` ก็ยังกดทำเองได้
- **ที่เก็บส่วนตัว:** ค่าเริ่มต้นเป็นโฟลเดอร์ `backups/` (ห้ามเป็นโฟลเดอร์ uploads ตรวจตอนโหลด config) หรือ storage adapter ที่ตั้งไว้ ไม่มี URL สาธารณะ หน้า admin เตือนเมื่อเก็บบนดิสก์ของ server เดียวกัน
- **ตารางภายใน `database-backups`** (มีทุกโปรเจกต์ ต้อง migrate ครั้งเดียว): สถานะ (pending/running/done/failed), ที่มา (manual/scheduled), ชื่อไฟล์ ขนาด เวลา error ผู้สั่ง และผู้ดาวน์โหลดล่าสุด
  - ใช้เป็นรายการแทนการ list จาก storage (StorageAdapter ไม่มี list)
  - ใช้เป็นล็อก: มีชุด pending/running ที่ยังไม่เกิน 30 นาทีอยู่ จะเริ่มชุดใหม่ไม่ได้ (409)
- **ทำในเบื้องหลัง:** `POST` ตอบ 202 ทันที `runJobs` (ทุกนาทีหรือจาก cron) ทำชุดที่ pending ค้างเกิน 30 นาทีต่อ และเปลี่ยนชุด running ที่ค้างเป็น failed ("Interrupted")
- **รอบอัตโนมัติ** ใน `runJobs`: รายวันทำหนึ่งครั้งต่อช่วงเวลา `at` รายสัปดาห์ทำเมื่อชุดตามรอบล่าสุดเก่ากว่าราวหนึ่งสัปดาห์ เวลาตามเขตเวลาของ server
- **การเก็บ:** เก็บชุดที่สำเร็จ `keep` ชุดล่าสุด (ลบทั้งไฟล์และแถว) แถวที่ล้มลบเมื่อเกิน 30 วัน
- **ดาวน์โหลดผ่าน server** เฉพาะ admin บันทึกผู้ดาวน์โหลดล่าสุด ไม่ใช้ presigned URL
- **ไม่มีการกู้คืนในหน้า admin:** กู้คืนบน server ตามเอกสาร (SQLite: แทนไฟล์, Postgres: `easy-cms copy` จากไฟล์ SQLite)
- **แจ้งใน "ต้องดูแล"** เมื่อชุดตามรอบล่าสุดล้ม หรือไม่มีชุดที่สำเร็จนานเกินสองรอบ (นับจากผู้ใช้คนแรกถ้ายังไม่เคยมี backup)
- **CLI `easy-cms backup`** ใช้กลไกเดียวกัน จึงรองรับ Postgres ด้วย ชื่อไฟล์ลงท้าย `.gz` จะถูกบีบอัด

## ผลที่ตามมา

- ✅ ทุกโปรเจกต์มี backup ได้โดยไม่ต้องติดตั้งเครื่องมือภายนอก และเตือนเมื่อ backup หยุดทำงาน
- ✅ ไฟล์เดียวรูปแบบเดียว เปิดดูด้วยเครื่องมือ SQLite ทั่วไปได้
- ⚠️ ไม่รวมไฟล์ที่อัปโหลด
- ⚠️ Postgres ขนาดใหญ่: การคัดลอกทั้งก้อนใช้เวลาและหน่วยความจำ (บีบอัดในหน่วยความจำ) ควรใช้ backup ของผู้ให้บริการควบคู่
- ❌ ยังไม่มีการเข้ารหัสในตัวและการกู้คืนจากหน้า admin (ตั้งใจ)
