# ADR-0032: แดชบอร์ดสำหรับ admin: ต้องดูแล และระบบ

- **สถานะ:** Accepted
- **วันที่:** 2026-10-04

## บริบท

- ปัญหาบางอย่างเงียบจนไม่มีใครเห็น:
  - webhook ที่ล้มจนเลิกลองถูกเก็บไว้ในตาราง `webhook-deliveries` แต่ไม่มีที่ไหนแสดง
  - อีเมลค้างในคิว
  - บน serverless ที่ไม่ได้ตั้ง cron การเผยแพร่ตามกำหนดเวลาจะไม่เกิดขึ้นเลย
- ตอนขอความช่วยเหลือ admin ไม่มีที่ดูว่าใช้เวอร์ชันอะไร ฐานข้อมูลอะไร และ plugin อะไรบ้าง
- plugin เป็นแค่ฟังก์ชัน `(config) => config` ไม่มีชื่อหรือเวอร์ชัน

## การตัดสินใจ

- **ชื่อและเวอร์ชันของ plugin:** `definePlugin(fn, { name, version })` อาร์กิวเมนต์ที่สองไม่บังคับ เก็บเป็น property `info` ของฟังก์ชัน
  - `resolveConfig` เก็บรายการไว้ใน `installedPlugins` ตามลำดับ plugin ที่ไม่มีชื่อเป็น `{}`
  - plugin-seo ใส่ `info` เองด้วย `Object.assign` เพราะโค้ดฝั่ง browser ของแพ็กเกจนี้ import ค่าจาก core ไม่ได้ (ADR-0028)
- **เวอร์ชันมาจาก `package.json` ตอน build:** tsup `define` (`__EASY_CMS_VERSION__` ใน core, `__PACKAGE_VERSION__` ใน plugin)
  - ไม่อ่าน `package.json` ตอนรัน เพราะ Nuxt และ Next.js อาจรวมโค้ดไว้ใน bundle ที่ไม่มีไฟล์นั้นข้าง ๆ
  - รันจาก source (test) ได้ `0.0.0-dev` แทน
  - core export `VERSION`
- **`GET <api>/admin/status`** เฉพาะ admin (API key ใช้ไม่ได้) แยกจาก admin schema เพราะต้องนับจากฐานข้อมูล และ editor ไม่ต้องได้ข้อมูลนี้
  - `system`: เวอร์ชัน ชื่อ adapter ของฐานข้อมูลและที่เก็บไฟล์ อีเมล (`EmailAdapter.name` ใหม่ ไม่บังคับ: `smtp`, `console` ไม่มีชื่อเป็น `custom`) plugin และชนิด field
  - `attention` ห้ารายการ:
    - webhook ที่ล้มใน 7 วัน (นับจาก `updatedAt` พร้อม URL ที่ล้มบ่อยที่สุดจาก 200 รายการล่าสุด)
    - อีเมลที่รอเกิน 1 ชั่วโมงหรือล้มใน 7 วัน
    - งานกำหนดเวลาที่ยัง pending หลังเวลาเกิน 10 นาที
    - ไม่มี `email`
    - `NODE_ENV=production` แต่ไม่มี `serverURL`
  - ไม่ติดต่อ npm เพื่อเช็กเวอร์ชันใหม่ เพราะไม่อยากให้ CMS ติดต่อออกไปข้างนอกเองโดยผู้ใช้ไม่ได้สั่ง
- **Admin:**
  - แถบ "ต้องดูแล" ใต้หัวหน้าแดชบอร์ด แสดงเฉพาะเมื่อมีรายการ แต่ละรายการลิงก์ไปหัวข้อในหน้า "Health checks" ของเอกสาร (EN/TH ตามภาษาของ admin)
  - กล่อง "ระบบ" ท้ายคอลัมน์ข้าง
  - ทั้งสองโหลดเฉพาะเมื่อผู้ใช้เป็น admin
- **dev server อ่าน shell ของ admin ใหม่ทุก request** (ไม่ใช่ production) ทั้ง `createAdminHandler` และ Nuxt module เพื่อให้ admin ที่ build ใหม่ระหว่างรันใช้งานได้ ไม่เป็นหน้าว่าง

## ผลที่ตามมา

- ✅ ปัญหาที่เงียบอยู่ปรากฏให้ admin เห็นพร้อมวิธีแก้
- ✅ ข้อมูลระบบสำหรับแจ้งปัญหาอยู่ในที่เดียว
- ⚠️ เปิดแดชบอร์ดแต่ละครั้ง admin จะมีการ query เพิ่มสามครั้ง (ใช้ index ของ `state`, `runAt`)
- ❌ ยังไม่มีหน้าในแอดมินสำหรับดูหรือส่ง webhook ที่ล้มซ้ำ ลิงก์ไปที่เอกสารแทน
