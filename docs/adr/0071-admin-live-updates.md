# ADR-0071: อัปเดตสดในหน้า admin

- **สถานะ:** Accepted
- **วันที่:** 2026-11-14
- **เกี่ยวข้อง:** [ADR-0070](0070-realtime.md) (realtime), [ADR-0069](0069-typescript-backend-six-levels.md)

## บริบท

- ADR-0070 ให้แอป subscribe การเปลี่ยนแปลงได้ แต่หน้า admin ยังไม่ใช้: สองคนแก้เอกสารเดียวกัน คนที่บันทึกทีหลังทับของอีกคนเงียบๆ
  และรายการไม่เปลี่ยนจนกว่าจะโหลดใหม่
- ตกลงกับเจ้าของโปรเจกต์ (2026-11-14) ก่อนลงมือ

## การตัดสินใจ

- **ขอบเขต:** หน้ารายการ, หน้าแก้ไข และ drawer ไม่มี presence หรือการล็อก และเซิร์ฟเวอร์ไม่ตอบ 409 (ไว้ทีหลัง)
- **เฉพาะ collection ที่มี `realtime: true`:** schema ของ admin (`GET <api>/admin/ui/schema`) บอกด้วย `realtime: true`
  collection อื่นทำงานเหมือนเดิมและไม่เปิด connection
- **หนึ่ง connection ต่อแท็บ:** ทุกหน้าในแท็บใช้ stream เดียว (`lib/realtime.ts`) หนึ่ง `s` ต่อสิ่งที่ตาม (หน้าที่ตามสิ่งเดียวกันใช้ร่วมกัน)
  - protocol เปลี่ยน subscription ของ stream ที่เปิดอยู่ไม่ได้ (ADR-0070) เมื่อหน้าเปิดหรือปิด จึงรอ 100 ms แล้วเปิด stream ใหม่
    ด้วย `Last-Event-ID` เท่ากับตำแหน่งของ stream เดิม (event ล่าสุด, `ready` หรือ heartbeat) ไม่พลาดอะไรระหว่างนั้น
  - client ของ core จึงรับ `subscribe(..., ..., { lastEventId })` และ handle บอก `lastEventId`
  - event ที่มาก่อน `ready` ของ subscription ที่เพิ่งเพิ่มอาจเป็นของก่อนหน้านั้นโหลด (replay): รายการไม่นับมันเป็นการเปลี่ยนแปลงใหม่
- **รายการ:** ตามทั้ง collection (ไม่ส่ง `where` ของรายการ เพราะ `where` ที่มี `like` เช่นการค้นหาจะไม่ได้ `delete`)
  - แถวที่แสดงอยู่: เปลี่ยนในที่ทันที (อ่านแถวนั้นใหม่แบบเดียวกับรายการ), ถูกลบ: จางลงพร้อมป้าย "ลบแล้ว" ไม่หายไปใต้เคอร์เซอร์
  - เอกสารใหม่หรือที่ออกจากมุมมองไม่แทรกหรือเอาออกเอง แต่นับเป็น "N changes — Show"
    มีตัวกรองอยู่ก็ถาม API ด้วย `where` ของรายการว่าเอกสารนั้นอยู่ในรายการหรือไม่ ก่อนนับ
  - กด Show โหลดรายการใหม่ด้วยหน้า การเรียง ตัวกรองเดิม และเก็บแถวที่เลือกไว้ที่ยังอยู่
  - `reset` แสดง "Changes — Show" (ไม่รู้จำนวน)
  - จุด "Live" ข้างหัวรายการ สีเทาพร้อม tooltip "Reconnecting…" เมื่อ stream หลุด ไม่มี toast
- **หน้าแก้ไขและ drawer:** ตามเอกสารเดียว (`draft: true` ถ้ามี drafts)
  - การบันทึกอื่น: ฟอร์มไม่มีสิ่งที่ยังไม่บันทึกก็โหลดฉบับใหม่เงียบๆ พร้อมข้อความ "Updated from the latest save";
    มีก็แสดง "This document was saved elsewhere" พร้อม "Load new version (discard mine)" และ "Keep mine"
    หลังจากนั้นการบันทึกถามก่อนทับ
  - `delete` / `leave`: แถบ "This document was deleted" / "You can no longer see this document" ปิดการบันทึก
    เนื้อหาที่แก้ยังอยู่ให้คัดลอก ไม่ redirect เอง
  - ไม่บอกว่าใครบันทึก ("saved elsewhere" รวมคนอื่นและแท็บอื่นของผู้ใช้เอง) และ event ไม่มีช่องว่าใครบันทึก
- **แยกการบันทึกของหน้าเองด้วยเนื้อหา ไม่ใช่ `updatedAt`:** `updatedAt` ของฉบับร่างของเอกสารที่ publish อยู่ที่อ่านได้ต่างจากที่การบันทึกตอบ
  (version เขียนทีหลังแถวเอกสาร) จึงจับคู่ไม่ได้
  - ระหว่างหน้าบันทึก โหลด ลบ หรือรัน action event รอไว้ก่อน แล้วอ่านเอกสารใหม่แบบเดียวกับหน้า
    และเทียบค่าในฟอร์มกับ baseline ที่การบันทึกตั้งไว้ เท่ากัน = การบันทึกของหน้าเอง (หรือไม่มีอะไรเปลี่ยน) ไม่ทำอะไร
  - `updatedAt` ใช้เพียงข้าม event ที่เก่ากว่าหรือเท่ากับที่หน้ามีอยู่ (ไม่ต้องอ่านใหม่)
- ข้อความ UI ภาษาอังกฤษและไทย, แถบและข้อความอยู่ใน `aria-live="polite"` ไม่ย้าย focus, จุด Live หยุดกะพริบเมื่อ reduced motion

## ผลที่ตามมา

- ✅ ไม่มีการทับเงียบๆ อีกในหน้า admin ของ collection ที่เปิด realtime
- ✅ หนึ่ง connection ต่อแท็บ ไม่ว่าจะเปิดรายการและ drawer พร้อมกัน (ขีดจำกัด `maxPerUser` 10 = ประมาณ 10 แท็บต่อผู้ใช้ต่อเซิร์ฟเวอร์)
- ⚠️ การเปลี่ยนแปลงแต่ละครั้งที่หน้าแก้ไขเห็นอ่านเอกสารใหม่หนึ่งครั้ง และรายการอ่านแถวที่เปลี่ยน (และถาม `where` เมื่อมีตัวกรอง)
- ⚠️ ยังมี race แคบๆ: การบันทึกสองที่พร้อมกันภายในเวลาเดียวกันยังทับกันได้ จนกว่าจะมี 409 ฝั่งเซิร์ฟเวอร์
- ⚠️ รายการตามทั้ง collection: collection ที่แก้บ่อยมาก event มาก แม้ตัวกรองแคบ
