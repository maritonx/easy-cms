# ADR-0033: หน้า "การส่ง" ใน admin (webhook และอีเมลที่ล้ม)

- **สถานะ:** Accepted
- **วันที่:** 2026-10-04

## บริบท

- แถบ "ต้องดูแล" (ADR-0032) บอกว่ามี webhook หรืออีเมลที่ล้ม แต่ลิงก์ได้แค่เอกสาร ไม่มีทางดูรายละเอียดหรือส่งซ้ำ
- รายการที่ล้มถูกเก็บไว้ตลอดไป ตารางจึงโตเรื่อย ๆ

## การตัดสินใจ

- **หน้าเดียวสองชนิด:** ตั้งค่า → การส่ง แท็บ Webhooks และอีเมล (แสดงเฉพาะชนิดที่มีตาราง) กรอง "ไม่สำเร็จ" และ "รอส่ง" เฉพาะ admin
  - admin schema บอก `deliveries: { webhook, email }` เฉพาะ admin เพื่อให้เมนูรู้ว่าควรแสดงไหม
- **API เฉพาะ admin (API key ใช้ไม่ได้):**
  - `GET <api>/admin/deliveries?kind&state&page` แสดงหน้าละ 50 ใหม่สุดก่อน พร้อมจำนวนของแต่ละสถานะ
  - `POST …/:kind/:id/retry` และ `POST …/:kind/retry` (ที่ล้มทั้งหมด)
  - `DELETE …/:kind/:id` และ `DELETE …/:kind` (ที่ล้มทั้งหมด)
  - อยู่ก่อนบล็อก `/admin/*` ที่รับแค่ GET
- **ส่งซ้ำ = ลองทันทีหนึ่งครั้ง** ไม่ใส่กลับเข้าคิว
  - สำเร็จ: ลบรายการ ล้ม: ยังเป็น `failed` เพิ่ม `attempts` และเก็บ error ใหม่ คนกดอยากรู้ผลเดี๋ยวนั้น และถ้าปลายทางยังพังอยู่ การเริ่มรอบลองใหม่ทั้งวันก็ไม่มีประโยชน์
  - webhook ใช้ header และ secret ปัจจุบันของ webhook ที่ URL ตรงกัน (`Webhooks.sendNow`) ถ้าถูกเอาออกจาก config แล้วจะล้มพร้อมบอกเหตุผล
  - อีเมลใช้ adapter ปัจจุบัน (`Mailer.sendNow`)
  - `EasyCMS.retryDelivery` เป็น `@internal`
  - "ส่งซ้ำทั้งหมด" เก็บ id ก่อนแล้วค่อยส่ง เพราะการส่งเปลี่ยนแถว (ที่สำเร็จถูกลบ) ทำให้การแบ่งหน้าเลื่อน
- **รายละเอียดที่แสดง:**
  - webhook: เหตุการณ์ เอกสารหรือ global ปลายทาง จำนวนครั้ง error เวลา และ body (เปิดดูได้)
  - อีเมล: ผู้รับและหัวเรื่องเท่านั้น ไม่แสดงเนื้อความ เพราะอาจมีข้อมูลส่วนตัวจากฟอร์ม
- **ลบอัตโนมัติ:** `runJobs` ลบรายการ `failed` ที่ `updatedAt` เกิน 30 วัน ส่วนแถบ "ต้องดูแล" ยังนับ 7 วันเหมือนเดิม
- แถบ "ต้องดูแล" ของ webhook และอีเมลลิงก์มาที่หน้านี้แทนเอกสาร ส่วนเอกสารลิงก์จากในหน้านี้

## ผลที่ตามมา

- ✅ admin แก้ปัญหาการส่งได้จากในหน้า admin
- ✅ ตารางของรายการที่ล้มไม่โตไม่สิ้นสุด
- ⚠️ "ส่งซ้ำทั้งหมด" ส่งทีละรายการใน request เดียว ถ้ามีหลายพันรายการจะใช้เวลานาน
