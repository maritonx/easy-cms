# ADR-0063: บังคับ SSO ด้วย `auth.password: { breakGlass }` ใน config

- **สถานะ:** Accepted
- **วันที่:** 2026-10-30

## บริบท

- องค์กรบังคับ MFA ไว้ที่ identity provider บัญชีที่ login ด้วยรหัสผ่านได้จึงเลี่ยง MFA ได้ ([#163](https://github.com/maritonx/easy-cms/issues/163))
- `auth.password: false` (มีอยู่แล้ว) ยังยอมให้ **admin ทุกคน** ใช้รหัสผ่าน ซึ่งเป็นบัญชีที่สำคัญที่สุด
- ทุกจุดที่ตรวจว่าใช้รหัสผ่านได้ไหมผ่าน `passwordAllowed()` ที่เดียว
- session ไม่ได้บันทึกว่า login มาด้วยวิธีไหน

## การตัดสินใจ

- **ใน config ไม่ใช่หน้า admin:** ถ้าเปลี่ยนได้จาก admin คนที่ถูกขโมยบัญชี admin ก็เปิดรหัสผ่านกลับมาได้ การกำหนดในโค้ดผ่านการรีวิวและมีประวัติใน git
- **`auth.password: true | false | { breakGlass: [emails] }`:**
  - `false` ทำงานเหมือนเดิม
  - `breakGlass` ระบุด้วย email ไม่สนตัวพิมพ์เล็กใหญ่ และต้องมี `auth.providers`
- **มีผลตอนเซิร์ฟเวอร์เริ่มทำงาน:**
  - เก็บนโยบายครั้งล่าสุดใน global `easy-cms:password-policy`
  - ถ้าต่างจากครั้งก่อน บันทึก `auth.password.policy` (ค่าก่อน/หลัง และจำนวน session ที่ปิด)
  - ปิด session ของบัญชีที่ใช้รหัสผ่านไม่ได้แล้ว เพราะ session ไม่บอกว่ามาจากรหัสผ่านหรือ SSO คนที่ใช้ SSO จึง login ใหม่หนึ่งครั้งด้วย
- **ปฏิเสธการตั้งรหัสผ่าน** ให้บัญชีที่ไม่ได้อยู่ในรายการ (`ValidationError`) ยกเว้นบัญชีแรกตอน setup ซึ่งยังไม่มีใครผูก SSO ได้ admin ซ่อนช่องรหัสผ่าน
- **การ login ของบัญชีฉุกเฉิน** บันทึกเป็น `login.breakGlass` และ dashboard แสดงไว้หนึ่งวัน
- **กันตัวเองล็อกออกหมด:** ถ้าไม่มีบัญชีในรายการที่มีอยู่จริงพร้อมรหัสผ่าน ให้เตือนใน log แต่ไม่หยุดการทำงาน

## ผลที่ตามมา

- ✅ ทุกบัญชีรวม admin ต้องผ่าน SSO และ MFA ยกเว้นบัญชีฉุกเฉินที่ระบุ ซึ่งการใช้ทุกครั้งมีคนเห็น
- ✅ ไม่ต้องเพิ่ม migration
- ⚠️ ตอนเปลี่ยนนโยบาย ทุกคนนอกจากบัญชีฉุกเฉินต้อง login ใหม่หนึ่งครั้ง
- ⚠️ ถ้าหลาย instance เริ่มพร้อมกัน อาจบันทึกการเปลี่ยนนโยบายซ้ำ
- ❌ เปลี่ยนนโยบายจากหน้า admin ไม่ได้ (ตั้งใจ)
