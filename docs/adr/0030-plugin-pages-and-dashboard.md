# ADR-0030: หน้าของ plugin และกล่องบนแดชบอร์ด (`admin.pages`, `admin.dashboard`)

- **สถานะ:** Accepted
- **วันที่:** 2026-10-04

## บริบท

- plugin เพิ่ม field, endpoint, component ใน field และแถบข้างของหน้าแก้ไข และชนิด field ได้แล้ว แต่ยังไม่มีที่ให้แสดงสิ่งที่ไม่ผูกกับเอกสารใดเอกสารหนึ่ง เช่น รายงาน
- form builder มีจำนวนข้อมูลที่ส่งมาแค่ในหน้าแก้ไขของแต่ละฟอร์ม ไม่มีภาพรวม
- แนวคิด "หน้าเต็มใน admin และ widget บน dashboard" อยู่ในรายการงานถัดไปของ DESIGN

## การตัดสินใจ

- **ใช้ Web Component ตามข้อตกลงเวอร์ชัน 1 เดิม** ไม่ใช้ iframe เพราะ iframe ใช้ธีมและ `api()` ของ admin ไม่ได้
- **`admin.pages: [{ path, component, label, icon?, group?, access? }]`**
  - อยู่ที่ `<admin>/p/<path>` (ใต้ `/p/` จึงไม่ชนกับ route ในตัว)
  - `path` ใช้ตัวพิมพ์เล็ก ตัวเลข และ `-` ห้ามซ้ำกัน (config error)
  - `group`: `'content'` (ค่าเริ่มต้น), `'settings'` หรือ `false` (ไม่อยู่ในเมนู เข้าทางลิงก์)
  - ยังไม่มีกลุ่มเมนูที่ตั้งชื่อเอง: รอให้มีหน้ามากพอก่อน
  - admin วาดส่วนหัว (breadcrumb, `label` เป็น H1, ชื่อแท็บ) component วาดเนื้อหา: หน้าตาเหมือนหน้าอื่นและมี H1 เดียว
- **`admin.dashboard: [{ component, width?, access? }]`**
  - อยู่ต่อจากกล่องในตัว ตามลำดับใน config
  - `half` (ค่าเริ่มต้น) หรือ `full` บนมือถือกว้างเต็มเสมอ
  - ยังซ่อนหรือเรียงกล่องในตัวไม่ได้
- **`access: ({ user }) => boolean`** ตรวจฝั่ง server ตอนสร้าง admin schema
  - หน้าที่ไม่มีสิทธิ์ไม่ถูกส่งไปเลย จึงไม่รู้ด้วยซ้ำว่ามีอยู่ (เปิด URL ตรงจะเจอ "ไม่พบ")
  - ถ้าฟังก์ชัน throw ถือว่าไม่มีสิทธิ์
  - เป็นแค่การซ่อน endpoint ที่ส่งข้อมูลต้องตรวจสิทธิ์เอง
- **ข้อตกลงของ element เพิ่มของใหม่โดยไม่เพิ่ม `apiVersion`:**
  - `user` (`id`, `email`, `role`) ให้ทุก component
  - `route` (`{ subpath, query }`) เฉพาะบนหน้าของ plugin
  - event `navigate` ที่ `detail` เป็น path ภายใน admin ใช้ทำแท็บ ช่วงเวลา และลิงก์ตรงที่รีเฟรชแล้วไม่หาย
  - รับเฉพาะ path ที่ขึ้นต้นด้วย `/` (ไม่รับ `//` หรือ URL ภายนอก)
- **ตัวอย่างจริงใน form builder:**
  - endpoint `GET <api>/form/stats.json?days=7|30&tz=` อ่านในนามผู้ใช้ (`overrideAccess: false`)
  - ใช้ `.json` เพราะ endpoint ที่มี segment คงที่ชนะ `/form/:slug` และ slug ไม่มีจุด จึงไม่ชนกับฟอร์มชื่อ `stats`
  - นับวันตามเขตเวลาของ browser (`tz`) ถ้าชื่อเขตเวลาไม่ถูกต้องใช้ UTC
  - หน้า "ภาพรวมฟอร์ม": กราฟรายวันและตารางแยกตามฟอร์มพร้อมลิงก์ไปข้อมูลที่ส่งมา ช่วงเวลาเก็บใน `?range=30`
  - กล่อง "7 วันล่าสุด": ยอดรวมและ 3 ฟอร์มที่ได้รับมากที่สุด (นับย้อนหลัง 7 วัน ไม่ใช่สัปดาห์ตามปฏิทิน เพื่อไม่ให้ตัวเลขตกเป็นศูนย์ทุกวันจันทร์)
  - กราฟเป็น HTML ธรรมดาใน module ไม่ใช้ไลบรารีกราฟ เพื่อให้ module อยู่ได้ในตัวเอง
- เพิ่มไอคอน `chart-column` และ `chart-line` สำหรับหน้ารายงาน

## ผลที่ตามมา

- ✅ plugin มีหน้าและกล่องบนแดชบอร์ดของตัวเองได้ โดยใช้ความรู้เรื่อง admin component ที่มีอยู่แล้ว
- ✅ form builder มีภาพรวมข้อมูลที่ส่งมาโดยไม่ต้องเปิดทีละฟอร์ม
- ⚠️ กล่องบนแดชบอร์ดแต่ละกล่องโหลดข้อมูลเอง ถ้ามีหลายกล่องจะมีหลาย request ตอนเปิดแดชบอร์ด
- ❌ ยังไม่มีกลุ่มเมนูที่ตั้งชื่อเอง และยังซ่อนหรือเรียงกล่องในตัวไม่ได้
