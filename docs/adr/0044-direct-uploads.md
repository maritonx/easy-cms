# ADR-0044: อัปโหลดไฟล์ใหญ่ตรงไปที่ storage และจำกัดการย้ายไฟล์

- **สถานะ:** Accepted
- **วันที่:** 2026-10-08

## บริบท

- โฮสต์แบบ serverless จำกัดขนาดของ request (Vercel ราว 4.5 MB, Netlify ราว 6 MB) ตั้งแต่ 0.39 คลังสื่อรับวิดีโอและเอกสารได้ แต่บน Vercel อัปไฟล์ใหญ่ไม่ได้ ไม่ว่าจะตั้ง `maxFileSize` เท่าไร
- 0.40 ย้ายไฟล์ข้าม storage ใน request เดียวเมื่อความเป็นส่วนตัวของโฟลเดอร์เปลี่ยน โฟลเดอร์ใหญ่อาจเกินเวลาของ function

## การตัดสินใจ

- **อัปโหลดตรงสามขั้น:** `createUpload` (`POST <api>/media/uploads`) ตรวจสิทธิ์ ขนาด และชนิดตามชื่อไฟล์ (ชนิดที่ browser ให้มาไม่คงที่) แล้วคืน URL อัปโหลดจาก storage (15 นาที) กับใบอัปโหลด browser ส่งไฟล์ไปที่ storage แล้ว `completeUpload` (`POST <api>/media/uploads/complete`) อ่าน 64 KB แรกและขนาดจริงจาก storage ตรวจชนิดจากเนื้อหาให้ตรงกับที่ประกาศ ขนาดให้ตรงและไม่เกิน `maxFileSize` ไฟล์ที่ไม่ผ่านถูกลบ รูปภาพดาวน์โหลดทั้งไฟล์เพื่อทำรูปย่อ
- **ใบอัปโหลดแทนตาราง:** ใบอัปโหลดเป็น JSON ที่เซ็น HMAC ด้วย `secret` (ชื่อไฟล์ใน storage, ส่วนตัวไหม, ชื่อ, ขนาด, ชนิด, ผู้ใช้, ฟิลด์อื่น, หมดอายุ 24 ชั่วโมง) จึงไม่ต้องมีตารางใหม่ ซึ่งจะบังคับ migration กับทุกโปรเจกต์ และใส่ตามชนิด storage ไม่ได้เพราะ starter เลือก storage ตอนรันจริง complete ได้ครั้งเดียว (ชื่อไฟล์ไม่ซ้ำ) และเฉพาะผู้ใช้ที่เริ่ม ข้อเสีย: ไฟล์ที่ส่งแล้วแต่ไม่มีใคร complete จะค้างใน storage โดยไม่มีที่ไหนลิงก์ถึง (เขียนไว้ในเอกสาร แนะนำ lifecycle rule ของ S3)
- **storage adapter:** เพิ่ม `uploadURL(key, { contentType, size, expiresIn })` และ `getStart(key, bytes)` แบบไม่บังคับ S3 ใช้ presigned PUT (SigV4 แบบ query) และ Range GET ส่วน Vercel Blob ใช้ client token ที่จำกัด pathname ขนาด ชนิด และเวลา ส่งไปที่ API เดียวกับ `@vercel/blob/client` และอ่าน stream แค่ส่วนต้น Netlify Blobs และดิสก์ไม่มี จึงอัปผ่าน server (`upload: null`)
- **admin ใช้อัตโนมัติ:** ไฟล์ใหญ่กว่า 4 MB ขอใบอัปโหลดก่อน ถ้า storage รับไม่ได้ก็ส่งผ่าน server เหมือนเดิม ส่วน starter ตั้ง `maxFileSize` 100 MB
- **จำกัดการย้ายไฟล์ไม่เกิน 200 ไฟล์:** ก่อนเปลี่ยนโฟลเดอร์เป็นส่วนตัวหรือสาธารณะ ย้ายโฟลเดอร์ หรือลบโฟลเดอร์ ระบบนับไฟล์ที่ความเป็นส่วนตัวจะเปลี่ยน (คำนวณจากต้นไม้หลังเปลี่ยน) ถ้าเกิน 200 ตอบ 400 พร้อมบอกให้ย้ายทีละส่วน ไม่ให้ตั้งค่าตัวเลขนี้

## ผลที่ตามมา

- ✅ อัปวิดีโอและเอกสารใหญ่บน Vercel ได้ ไม่ต้องมี migration ใหม่
- ✅ server ยังตรวจทุกไฟล์จากเนื้อหาเหมือนเดิม
- ⚠️ S3 ต้องตั้ง CORS ให้ origin ของ admin และ Vercel Blob พึ่ง API ของ `@vercel/blob/client` ที่ไม่ได้ประกาศเป็น API สาธารณะ
- ❌ ไฟล์ที่ค้างจากการ complete ไม่สำเร็จยังไม่ถูกลบเอง และโฟลเดอร์ที่มีไฟล์เกิน 200 ไฟล์ต้องย้ายทีละส่วน
