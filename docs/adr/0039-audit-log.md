# ADR-0039: Audit log

- **สถานะ:** Accepted
- **วันที่:** 2026-10-05

## บริบท

- องค์กรต้องตรวจย้อนหลังได้ว่าใครแก้ field ไหน ลบเอกสารอะไร เข้าสู่ระบบเมื่อไร และผู้ดูแลระบบเปลี่ยนสิทธิ์อะไร
- versions เก็บ snapshot เฉพาะ collection ที่เปิด versions จำกัดจำนวน และถูกลบไปพร้อมเอกสาร จึงใช้เป็น audit log ไม่ได้ ส่วนประวัติอื่น (บทบาท ผู้ดาวน์โหลด backup) กระจายอยู่คนละที่
- database adapter ไม่มี transaction ข้ามตาราง

## การตัดสินใจ

- **เปิดเองด้วย `audit`** (`true` หรือ `{ keep = 365, values = true, failedLogins = 20 }`) เพิ่มตารางภายใน `audit-logs` เฉพาะเมื่อเปิด
- **บันทึก:** การเปลี่ยนเนื้อหาทุกจุดที่ส่ง webhook event (create/update/draft/delete ทั้ง collection และ global) แยก publish, unpublish และ restore ออกจาก update รวมการตั้งเวลา การเข้าสู่ระบบ (สำเร็จ ไม่สำเร็จ ถูกล็อก logout ลืมรหัส ลิงก์รหัส SSO) และการจัดการระบบ (บทบาท backup อีเมลทดสอบ การส่งซ้ำ) ผู้ใช้และ API key เป็นการเปลี่ยนเนื้อหาของ collection อยู่แล้ว จึงได้ diff ของ role และ active ไปเอง ไม่บันทึกการอ่าน
- **diff ระดับ field** ชั้นบนสุด ค่าก่อนและหลัง ไม่เก็บ field ที่ `hidden` (รหัสผ่านแสดงแค่ว่าเปลี่ยน) rich text, blocks, array และ json เก็บแค่ว่าเปลี่ยน ค่ายาวเกิน 500 ตัวอักษรถูกตัด `values: false` เก็บแค่ชื่อ field การลบเก็บชื่อเอกสาร
- **ผู้กระทำ:** id และอีเมลตอนนั้น ช่องทาง (`user`, `api-key` พร้อมชื่อ key, `system`, `scheduler`) IP และ user agent ส่งผ่าน `AsyncLocalStorage` (`auditContext`) ที่ REST handler และ `runJobs` ตั้งไว้ ทุกชั้น (Local API, Auth, Roles, plugin) จึงรู้ผู้กระทำโดยไม่ต้องส่งต่อเป็น parameter การเรียก Local API แบบ trusted จากโค้ดบันทึกเป็น `system`
- **append-only + ลายเซ็น:** ไม่มี endpoint แก้หรือลบ ลบได้แค่ตามอายุจากเก่าสุด แต่ละแถวลงลายเซ็น HMAC-SHA256 ด้วย `secret` จาก JSON ที่เรียง key แล้ว (jsonb ของ Postgres เรียง key ใหม่) การตรวจหาแถวที่ลายเซ็นไม่ตรงและ id ที่ขาด เลือกแทน hash chain เพราะ chain เพี้ยนเมื่อหลาย server เขียนพร้อมกัน ข้อจำกัด: ตรวจไม่พบคนที่รู้ secret หรือการลบแถวท้ายสุด และ insert ที่ล้มใน Postgres ก็ทำให้ id ขาดได้ (รายงานเป็น "หายไป" พร้อมหมายเหตุ)
- **fail-open:** บันทึกไม่สำเร็จไม่ทำให้การแก้ไขล้ม นับจำนวนไว้และแจ้งบนแดชบอร์ด
- **งานรายวัน** ใน `runJobs`: ลบตามอายุ แล้วตรวจความถูกต้อง ผลการตรวจเก็บเป็นรายการ `audit.verify` แดชบอร์ดเตือนเมื่อพบรายการถูกแก้ เมื่อบันทึกไม่สำเร็จ และเมื่อ login ไม่สำเร็จเกินเกณฑ์ในหนึ่งชั่วโมง
- **ผู้ดู:** admin และบทบาทที่ได้หน้า `audit` ใน ตั้งค่า → Roles หน้า Audit log มีตัวกรอง diff ส่งออก CSV (กันสูตร spreadsheet) และปุ่มตรวจ หน้าเอกสารมีกล่อง "กิจกรรม"

## ผลที่ตามมา

- ✅ ตรวจย้อนหลังได้ครบในที่เดียว แม้เอกสารหรือผู้ใช้ถูกลบไปแล้ว
- ✅ ตรวจพบการแก้ log ในฐานข้อมูลโดยคนที่ไม่มี secret
- ⚠️ ทุกการเขียนมี insert เพิ่มหนึ่งครั้ง
- ❌ ยังไม่ส่ง log ออกไปที่อื่นแบบ real-time (ใช้ webhook ได้บางส่วน) และไม่บันทึกการอ่าน
