# ADR-0034: หน้า ตั้งค่า → อีเมล (ดูค่าและทดสอบ)

- **สถานะ:** Accepted
- **วันที่:** 2026-10-04

## บริบท

- คำถามที่พบบ่อยที่สุดเรื่องอีเมลคือ "ตั้งค่าแล้วส่งได้ไหม และถ้าไม่ได้ error คืออะไร" แต่ admin ไม่มีที่ดูค่าหรือทดสอบ ต้องรอให้ผู้ใช้ขอลิงก์ลืมรหัสผ่านแล้วไล่ดู log
- ผู้ใช้ขอให้แก้ค่า SMTP ได้ในหน้า admin แต่นั่นหมายถึงการเก็บรหัสผ่าน SMTP ในฐานข้อมูล ซึ่งเป็นการตัดสินใจเรื่องความปลอดภัยที่ใหญ่กว่า

## การตัดสินใจ

- **รอบนี้ทำแค่ดูค่าและทดสอบ** การแก้ค่าในหน้า admin (เก็บรหัสผ่านแบบเข้ารหัสในฐานข้อมูล) เลื่อนไปคุยแยก ค่ายังมาจาก config และ env
- **adapter บอกรายละเอียดตัวเอง** ผ่านเมธอดที่ไม่บังคับใน `EmailAdapter`:
  - `describe()` คืน `{ key, value, source }[]` ห้ามคืนความลับ (รหัสผ่านบอกแค่ `set`) admin แปลชื่อ key ที่รู้จัก (`host`, `port`, `secure`, `user`, `password`, `from`, `delivery`) ที่เหลือแสดงตามที่ส่งมา
  - `verify()` ตรวจการเชื่อมต่อโดยไม่ส่ง
  - adapter ไหนไม่มีก็แสดงแค่ชื่อและผู้ส่ง ไม่มีปุ่มตรวจ
  - `smtp()` บอกที่มาของแต่ละค่า (option หรือชื่อ env) และ `verify()` ใช้ `transporter.verify()` ของ nodemailer
  - `consoleEmail()` บอกว่าพิมพ์ลง log ไม่ได้ส่งจริง
- **API เฉพาะ admin (API key ใช้ไม่ได้):** `GET <api>/admin/email`, `POST …/verify`, `POST …/test` พร้อม `{ to?, locale? }`
- **อีเมลทดสอบส่งตรง ไม่ผ่านคิว** เพื่อให้ได้คำตอบจริงของ server ทันที
  - ส่งถึง admin ที่กดเป็นค่าเริ่มต้น แก้เป็นที่อยู่อื่นได้
  - เนื้อหาคงที่ (ชื่อเว็บ ผู้ส่ง adapter เวลา) ตามภาษาของ admin เพื่อไม่ให้หน้านี้ใช้ส่งอีเมลอะไรก็ได้
  - จำกัด 5 ครั้งต่อ 10 นาทีต่อ admin ต่อ instance (เก็บในหน่วยความจำ บน serverless จึงเป็นการกันแบบหลวม ๆ)
- **คำแนะนำสำหรับ error ที่พบบ่อย** จับจากข้อความ error ในหน้า admin: user/รหัสผ่าน, TLS กับ port, ติดต่อไม่ได้, ผู้ส่งถูกปฏิเสธ, ไม่ได้ตั้ง host

## ผลที่ตามมา

- ✅ admin ตรวจและแก้ปัญหาอีเมลได้เองโดยไม่ต้องเปิด log
- ✅ ไม่มีความลับถูกเก็บหรือส่งออกไปเพิ่ม
- ⚠️ การแก้ค่ายังต้องแก้ env แล้ว restart
- ❌ การจำกัดจำนวนครั้งไม่แชร์กันระหว่างหลาย instance
