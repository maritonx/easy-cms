# ADR-0066: ค่าในโค้ดเป็นค่าเริ่มต้น และ admin เปลี่ยนได้

- **สถานะ:** Accepted
- **วันที่:** 2026-11-10
- **เกี่ยวข้อง:** [ADR-0065](0065-code-first-application-engine.md), [ADR-0004](0004-code-first-content-model.md)

## บริบท

- หน้า Integrations มีหมวด "ตั้งในโค้ด" ที่แสดงอีเมล ที่เก็บไฟล์ และการเข้าสู่ระบบ ซึ่งแก้ได้แค่ในโค้ดแล้ว deploy ใหม่
- เจ้าของโปรเจกต์ต้องการให้ admin เชื่อมต่อบริการเหล่านี้ได้เองในหน้า admin โดยค่าในโค้ดเป็นค่าเริ่มต้น (grilling 2026-11-10)
- Settings → Backups (1.41) ใช้กติกาตรงข้าม คือค่าในโค้ดชนะ และ admin แก้ไม่ได้

## การตัดสินใจ

- **ลำดับค่า:** ค่าที่ admin ตั้ง → ค่าในโค้ด → ค่าเริ่มต้นของระบบ
- **dev ล็อกได้:** เช่น `backups.locked: true` ค่าในโค้ดชนะ และหน้า admin แสดงกุญแจ
- **บันทึกค่าเท่ากับค่าในโค้ด = ไม่เก็บ:** ถ้า dev เปลี่ยนค่าในโค้ดภายหลัง ค่าใหม่จะมีผล
  และมีปุ่ม "ใช้ค่าจากโค้ด" ไว้กลับไปเสมอ
- **ทำตามลำดับความเสี่ยง:**
  1. Backups (1.41)
  2. อีเมลผ่าน `@easy-cms/plugin-email`
  3. การเข้าสู่ระบบ
  4. ที่เก็บไฟล์
- **บริการที่ตั้งจาก admin มาจาก integrations:**
  - ตัวเชื่อมของแต่ละแพ็กเกจ เช่น `defineEmailProvider` บอกว่าต้องกรอกอะไรและสร้าง adapter อย่างไร
  - core ไม่รวม dependency ของทุกเจ้า
- **ความปลอดภัยของการเปลี่ยน:**
  - ต้องทดสอบผ่านก่อนสลับ เช่น ส่งอีเมลทดสอบถึง admin
  - บัญชีที่ใช้อยู่ลบหรือปิดไม่ได้
  - เฉพาะ admin ของทั้งเว็บที่เปลี่ยนได้ และบันทึกทุกการเปลี่ยนใน audit log
- **หลายเซิร์ฟเวอร์:** ค่าที่ admin ตั้งเก็บในฐานข้อมูล แต่ละ instance อ่านใหม่ทุก 30 วินาที จึงไม่ต้อง deploy ใหม่
- **ความลับ:** ความลับที่กรอกใน admin เข้ารหัสด้วย `secret` เหมือน integrations อื่น ค่าใน env ถือเป็นค่าของโค้ด

## ผลที่ตามมา

- หน้า admin ต้องบอกเสมอว่าค่ามาจากไหน: จากโค้ด, admin เปลี่ยนแล้ว หรือล็อก
- ฟีเจอร์ที่เคยตรวจ `config.email` ตรงๆ ต้องถามค่าที่ใช้อยู่ตอนนี้ (`cms.emailAdapter()`) แทน
- การเข้าสู่ระบบและที่เก็บไฟล์ต้องกันความเสียหายเพิ่ม:
  - **การเข้าสู่ระบบ:** admin ต้องไม่ล็อกตัวเองออก และมีคำสั่ง `easy-cms reset-sign-in` สำหรับกู้คืน
  - **ที่เก็บไฟล์:** บันทึกที่เก็บของแต่ละไฟล์ เพื่อให้ไฟล์เก่ายังเปิดได้หลังเปลี่ยนที่เก็บ
