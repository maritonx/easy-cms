# ADR-0043: ไฟล์ส่วนตัว key ของโฟลเดอร์ และ API key ตามโฟลเดอร์

- **สถานะ:** Accepted
- **วันที่:** 2026-10-07

## บริบท

- ใน 0.38 สิทธิ์โฟลเดอร์ใช้แบ่งงานของทีมเท่านั้น ไฟล์ทุกไฟล์ยังเป็นสาธารณะ เสิร์ฟจาก `/media/file/<key>` หรือ CDN ของ storage องค์กรเก็บเอกสารภายในหรือไฟล์สำหรับสมาชิกในคลังสื่อไม่ได้
- ช่อง upload ในโค้ดระบุโฟลเดอร์ไม่ได้ เพราะโฟลเดอร์เป็นข้อมูลที่เปลี่ยนชื่อได้ ([ADR-0041](0041-media-folders.md)) และ API key ยังจำกัดตามโฟลเดอร์ไม่ได้

## การตัดสินใจ

- **ส่วนตัวตั้งที่โฟลเดอร์ สืบทอดลงไป:** `private` บนโฟลเดอร์ (admin ตั้งได้เท่านั้น) ไฟล์มี `private` ที่ระบบตั้งตามโฟลเดอร์ เพื่อให้กรองได้ในคำสั่งเดียว ไฟล์ก่อน 0.40 มีค่า NULL จึงถือว่า "ไม่ส่วนตัว" คือ `false` หรือไม่มีค่า (`!= true` ใน SQL ไม่จับ NULL)
- **ชื่อไฟล์บอกว่าส่วนตัว:** `ชื่อ-สุ่ม.private.นามสกุล` และรูปย่อ `ชื่อ-สุ่ม.private-ขนาด.นามสกุล` route สาธารณะรับเฉพาะชื่อที่มีจุดเดียวอยู่แล้ว จึงไม่มีทางเสิร์ฟไฟล์ส่วนตัว แม้ไฟล์ส่วนตัวกับสาธารณะจะอยู่ใน storage เดียวกัน
- **ที่เก็บ:** `upload.privateStorage` ถ้าไม่ได้ตั้ง ใช้ storage หลักเมื่อมันไม่มี `url()` (ดิสก์, Netlify Blobs) storage ที่มี `url()` (S3, Vercel Blob) ถือว่าอาจให้ URL สาธารณะ จึงทำโฟลเดอร์ส่วนตัวไม่ได้จนกว่าจะตั้ง `privateStorage` ตรวจตอนบันทึกโฟลเดอร์ starter บน Vercel ใช้ `vercelBlobStorage({ access: 'private', prefix: 'private/' })`
- **เสิร์ฟ:** `GET <api>/media/private/<key>` ให้ (1) ลิงก์ที่เซ็น `?expires=&signature=` HMAC-SHA256 ด้วย `secret` ของ `media:<key>:<expires>` เทียบแบบ timing-safe หรือ (2) ผู้ใช้ที่ล็อกอินและอ่านเอกสาร media นั้นได้ (หาเอกสารจากเลขสุ่ม 8 หลักในชื่อ ผ่าน `find` ที่ตรวจบทบาทและสิทธิ์โฟลเดอร์) นอกนั้นตอบ 404 เพื่อไม่ให้เดาชื่อไฟล์ได้ header: `private, max-age=300`, `nosniff` และ CSP sandbox ยกเว้น PDF
- **`cms.signedMediaURL(doc, { expiresIn, size })`:** ค่าเริ่มต้น 1 ชั่วโมง สูงสุด 7 วัน ไฟล์สาธารณะได้ URL ปกติ ลิงก์หมดอายุเมื่อเปลี่ยน `secret` หรือไฟล์ไม่เป็นส่วนตัวแล้ว (ชื่อเปลี่ยน)
- **ผู้ที่ไม่ได้ล็อกอินไม่เห็นไฟล์ส่วนตัว:** `MediaFolders.where` เพิ่มเงื่อนไขไฟล์สาธารณะให้คำขอที่ไม่มีผู้ใช้ การ populate จึงไม่ส่งรูปปกส่วนตัวให้ผู้เยี่ยมชมด้วย
- **ย้ายข้าม storage:** เมื่อไฟล์ย้ายโฟลเดอร์ หรือโฟลเดอร์เปลี่ยนเป็นส่วนตัวหรือสาธารณะ ย้ายโฟลเดอร์ หรือถูกลบ (ของข้างในย้ายขึ้นไป) ระบบคัดลอกไฟล์และรูปย่อทุกขนาดไปอีก storage ด้วยชื่อใหม่ บันทึกเอกสาร แล้วจึงลบของเดิม ทำทันทีใน request (โฟลเดอร์ที่มีไฟล์มากจะช้า) admin ยืนยันก่อนพร้อมจำนวนเอกสารที่ใช้ไฟล์ (`GET <api>/admin/media-usage?ids=` นับเฉพาะ upload field ชั้นบนสุด ไม่นับ rich text)
- **key ของโฟลเดอร์:** `key` ตั้งได้ตอนสร้างเท่านั้น และไม่ซ้ำ `{ type: 'upload', folder: 'banners' }` หาโฟลเดอร์จาก key และสร้างให้ที่ชั้นนอกสุดเมื่อใช้ครั้งแรก (ตอน admin ขอ schema) แทนตอนเริ่มระบบ เพื่อไม่ให้ cold start ต้องเขียนฐานข้อมูล `folderOnly` ตรวจตอนบันทึกว่าไฟล์อยู่ในโฟลเดอร์นั้นหรือโฟลเดอร์ย่อย และตัวเลือกไฟล์ของ admin ไม่ให้ขึ้นไปเหนือโฟลเดอร์นั้น
- **API key ตามโฟลเดอร์:** `permissions.folders` (id ของโฟลเดอร์ รวมโฟลเดอร์ย่อย ไม่มีหรือว่าง = ทุกโฟลเดอร์) จำกัดทุก operation ของ key กับ media และ media-folders รวมถึงการอ่านไฟล์ส่วนตัว key ที่จำกัดไว้ไม่เห็นไฟล์ชั้นนอกสุด

## ผลที่ตามมา

- ✅ เก็บเอกสารภายในและไฟล์สำหรับสมาชิกในคลังสื่อได้ ให้ดาวน์โหลดผ่านลิงก์ที่มีอายุ
- ✅ ช่อง upload ในโค้ดผูกกับโฟลเดอร์ได้โดยไม่เปราะเมื่อมีคนเปลี่ยนชื่อ
- ⚠️ การเปลี่ยนโฟลเดอร์ที่มีไฟล์มากเป็นส่วนตัวหรือสาธารณะ คัดลอกไฟล์ทั้งหมดใน request เดียว และ URL ของไฟล์เปลี่ยน
- ⚠️ เบราว์เซอร์อาจใช้สำเนาใน cache ของตัวเองได้ 5 นาทีหลัง logout
- ❌ ยังไม่นับการใช้ไฟล์ใน rich text และ field ที่ซ้อนอยู่ข้างใน ตอนเตือนก่อนย้าย
