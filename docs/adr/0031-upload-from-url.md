# ADR-0031: อัปโหลดจากลิงก์ (`upload.fromURL`)

- **สถานะ:** Accepted
- **วันที่:** 2026-10-04

## บริบท

- คนที่ย้ายเนื้อหาจากเว็บเดิมต้องดาวน์โหลดรูปลงเครื่องก่อนแล้วค่อยอัปโหลดใหม่ทีละไฟล์
- การให้ server ดาวน์โหลดแทนเปิดช่อง SSRF: ลิงก์อาจชี้ไปที่ service ภายใน (`localhost`, `10.x`) หรือ metadata ของ cloud (`169.254.169.254`) ที่มี credential

## การตัดสินใจ

- **API:**
  - `cms.uploadFromURL(url, data?, options?)` ดาวน์โหลดแล้วส่งต่อให้ `cms.upload()` จึงตรวจชนิดไฟล์จากเนื้อไฟล์ ขนาด และสิทธิ์สร้าง media เหมือนเดิมทุกอย่าง
  - REST ใช้ `POST <api>/media` เดิม แยกตาม content-type: JSON `{ url, ...fields }` หรือ multipart แบบเดิม
- **ปิดไว้เป็นค่าเริ่มต้น** เปิดด้วย `upload.fromURL: { allowedHosts, allowPrivate? }`
  - `allowedHosts`: ชื่อตรงตัว, `*.domain` (เฉพาะ subdomain ไม่รวม domain เอง) หรือ `*` เทียบแบบไม่สนตัวพิมพ์และพอร์ต
  - การเรียกในนามผู้ใช้ (REST, `overrideAccess: false`) ต้องมี `fromURL` และ host ต้องอยู่ใน `allowedHosts`
  - โค้ดของโปรเจกต์เอง (ไม่มี user) ไม่ต้องตั้งและไม่สน `allowedHosts` แต่ยังกันที่อยู่ภายใน
  - ตรวจสิทธิ์และการเปิดใช้ **ก่อน** ดาวน์โหลด เพื่อไม่ให้ผู้ไม่มีสิทธิ์สั่ง server ส่ง request ได้
- **กัน SSRF:**
  - รับเฉพาะ `http`/`https` และลิงก์ที่ไม่มีรหัสผ่าน
  - กันที่อยู่ภายในด้วย `net.BlockList`: loopback, private, link-local, CGNAT, multicast, ช่วงที่สงวนไว้ รวม IPv6 และ IPv4-mapped IPv6
  - ตรวจ **หลัง resolve DNS** ผ่าน `lookup` ของ `http.request` เพื่อกัน DNS rebinding (ใช้ IP ที่ตรวจแล้วเชื่อมต่อจริง) ส่วน IP ที่เขียนตรงใน URL ตรวจก่อนส่ง
  - จัดการ redirect เอง (ไม่เกิน 3 ครั้ง) และตรวจ host กับที่อยู่ซ้ำทุกขั้น
  - `allowPrivate: true` ยกเลิกเฉพาะกฎที่อยู่ภายใน สำหรับ server ในอินทราเน็ต เป็นตัวเลือกแยกที่ต้องตั้งเอง ไม่ใช่ยกเว้นให้ host ที่เขียนไว้ใน `allowedHosts` อัตโนมัติ
- **ขีดจำกัดคงที่:** timeout 15 วินาทีรวม redirect หยุดอ่านเมื่อเกิน `maxFileSize` (ไม่โหลดมาก่อนทั้งไฟล์) ตอบ 413 ถ้าใหญ่เกิน
- **ชื่อไฟล์:** จาก `Content-Disposition` (รวม `filename*`) ถ้าไม่มีใช้ส่วนท้ายของ path ถ้าไม่มีอีกใช้ `download`
- **ไม่เก็บ URL ต้นทาง** ใน media เพื่อไม่ให้ทุกโปรเจกต์ต้อง migrate ถ้าต้องการให้ส่งไปใน `data` ของ field ตัวเอง
- **Admin:**
  - schema มี `uploadFromURL` พื้นที่อัปโหลด (คลังสื่อ ตัวเลือกสื่อ แกลเลอรี) แสดงช่อง "จากลิงก์" เมื่อเปิดใช้
  - วางลิงก์หรือไฟล์ลงในพื้นที่อัปโหลด (โฟกัสได้) และลากรูปจากหน้าเว็บอื่น (`text/uri-list`) มาวางได้
  - ช่องลิงก์ไม่ใช้ `<form>` เพราะพื้นที่อัปโหลดอยู่ในฟอร์มแก้ไขได้
- ตัวอย่างทั้งสามเปิด `allowedHosts: ['*']` โดยไม่เปิด `allowPrivate` การดึงไฟล์จริงทดสอบใน integration test ด้วย server ในเครื่องที่เปิด `allowPrivate` ส่วน e2e ตรวจว่าลิงก์ `localhost` ถูกปฏิเสธพร้อมข้อความ

## ผลที่ตามมา

- ✅ ย้ายเนื้อหาได้ง่ายขึ้น ทั้งจาก admin และ script
- ✅ ช่องทาง SSRF ที่พบบ่อย (IP ภายใน, DNS rebinding, redirect ไปที่อยู่ภายใน) ถูกกันไว้ตั้งแต่ต้น
- ⚠️ ทำงานบน Node เท่านั้น (ใช้ `node:http`, `node:dns`) เหมือนส่วนอื่นของ core
- ⚠️ proxy ขาออกของบริษัท (`HTTP_PROXY`) ยังไม่รองรับ
- ❌ ยังไม่ดึงรูปให้อัตโนมัติตอนวางเนื้อหาลงใน rich text
